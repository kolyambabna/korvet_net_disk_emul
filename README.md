# Сетевой монитор КОРВЕТ CP/N-90 — Python-порт (`pcndr.py`)

**Версия: 1.01p** · Кроссплатформенно: Linux / Windows · Python ≥ 3.8

Функциональный аналог сетевого монитора `NDR` из комплекта сетевой ОС
**CP/N-90** (корветовские классы КУВТ). Монитор эмулирует сервер сети по
последовательному порту и позволяет:

* **сетевой загрузить CP/M** в Корвет-РМУ (ПК8010 без дисководов, либо ПК8020
  в режиме РМУ) — первичным загрузчиком и образом клиентской системы;
* **эмулировать сетевые диски A:, B:, E:** по образам формата **KDI**
  (только чтение — как в оригинальной C-версии);
* обслуживать запросы сетевой CP/M: чтение абсолютных секторов, последовательное
  чтение файлов, открытие/закрытие/создание/переименование/удаление, запись.

Оригинал на C: `main.c`, `std_lan.c`, `kdi.c` (автор — Alexander Stepanov
aka `forth32`, forth32@mail.ru). Общий обзор системы, подключение Корвета
переходником TTL↔RS-232/USB, цоколевка разъёма XS5 и установка сетевого адреса
перемычками — в [корневом README проекта](../README).

## Быстрый старт

1. Установить зависимости (нужна только `pyserial`):

   ```bash
   pip install -r py/requirements.txt
   ```

2. Проверить, что в **текущем каталоге** (корень проекта) есть системные файлы:
   `cpn90ldr.bin`, `cpn90img.bin`, `cpn90sys.bin`, а образы дисков — в `disk/`.

3. Подключить Корвет (см. [корневой README](../README)): переходник уровней
   сигнала к разъёму XS5, перемычки A0–A3 задают адрес РМУ (по умолчанию
   монитор рассчитывает на **адрес 2** — замкнутая линия A1).

4. Запустить монитор **из корня проекта**:

   ```bash
   # Linux
   python py/pcndr.py -a disk/sys.kdi -b disk/ESL_12.kdi -s /dev/ttyUSB0

   # Windows
   python py\pcndr.py -a disk\sys.kdi -b disk\ESL_12.kdi -s COM3
   ```

5. Перевести Корвет в ROM-Бейсик (он включается сам, если назначен адрес ≠ 0) —
   монитор сам пошлёт загрузчик и образ системы, после чего можно запускать
   программы с сетевого диска `A:`.

Имя последовательного устройства в Linux видно в `dmesg` после подключения
переходника (`/dev/ttyUSBx` или `/dev/ttyACMx`).

## Ключи командной строки

Совместимы с C-версией; добавлен только отладочный ключ `-d`.

| Ключ | Арг. | По умолчанию | Назначение |
|------|------|--------------|------------|
| `-a` | файл | `disk/sys.kdi` | образ KDI для диска **A:** (обязателен, иначе — аварийный выход) |
| `-b` | файл | *(пусто)* | образ KDI для диска **B:** |
| `-e` | файл | *(пусто)* | образ KDI для диска **E:** |
| `-s` | устр. | `/dev/ttyS0` | последовательный порт: `/dev/ttyS0`, `/dev/ttyUSB0`, `COM3`, … |
| `-n` | 1–15 | `2` | адрес РМУ, заданный перемычками A0–A3 (диапазон проверяется) |
| `-x` | — | — | пропустить загрузку системы (ОС уже в РМУ, напр. после выхода из монитора для смены диска) |
| `-d` | — | — | отладочная печать сетевого обмена (`@`-строки: адресация, пакеты, передачи) |
| `-h` | — | — | справка |

Параметры порта жёстко фиксированы, как в оригинале: **19200 8O1**
(8_data, odd parity, 1 stop), без аппаратного/программного flow control.
Таймаут ожидания байта из сети — 0,1 с (в C — `VTIME=1`).

## Клавиши управления во время работы

| Клавиша | Действие |
|---------|----------|
| `r` | повторная загрузка ОС в Корвет (напр. после Reset на РМУ) |
| `x` | выход из монитора (аналогично Ctrl+C) |

Реализация — [`console.py`](console.py): в Windows через `msvcrt` (работает
в обычном окне cmd/PowerShell/Terminal), в Linux/macOS терминал переводится в
cbreak-режим и восстанавливается при выходе. Если stdin перенаправлен (не
терминал), клавиши недоступны — выход по Ctrl+C.

## Типовой сеанс

```text
 $ python py/pcndr.py -a disk/sys.kdi -b disk/ESL_12.kdi -s /dev/ttyUSB0

 ***  Сетевой монитор КОРВЕТ CP/N-90 версия 1.01p ***

 + Чтение каталога диска A
 + Чтение каталога диска B
 + Посылка загрузчика....
 + Посылка образа системы:  /
 + Загрузка системы окончена
 + Ждем команду от клиента
 + Открытие файла U0: A:PIP     COM
 + Запрос сектора: диск A дорожка 2 сектор 32
 + Чтение файла U0: A:PIP     COM - сектор 57     - Пересылка завершена
```

Строка «Ждем команду от клиента» появляется сразу после загрузки — монитор
опрашивает сеть маркером и перехватывает запросы РМУ.

## Что происходит при запуске

1. Разбор ключей, проверка адреса РМУ (1–15).
2. Открытие порта `19200 8O1`, сброс буферов; формирование **маркера опроса**
   `FF 80|адрес`.
3. Открытие `cpn90sys.bin`, образов KDI; чтение каталогов всех заданных дисков
   (разбор инфосектора и записей с склейкой экстентов — `kdi.py`).
4. Без `-x`: посылка загрузчика `cpn90ldr.bin` (тип 7, адрес `0xEEEE`),
   задержка 200 мс, затем перекидка `cpn90img.bin` по 128 байт (88 секторов).
5. Главный цикл: отправка маркера → приём 34-байтного командного пакета →
   проверка КС (ответ `Y`/`N`) → диспетчер по коду функции → отклик сектором
   данных / содержимым файла / подтверждением.

Подробный формат всего, что летает по порту — [docs/PROTOCOL.md](docs/PROTOCOL.md).

## Эмулируемые диски

* **A:, B:, E:** — сетевые диски по образам KDI. Параметры файловой системы
  берутся из инфосектора образа (число секторов, размер блока, каталог);
  стандартная конфигурация CP/M — 2 системные дорожки, 128 записей каталога,
  блоки 2 КБ. Нестандартные образы (напр. от MICRODOS) не поддерживаются —
  как и в оригинале.
* При доступе с буквы **E:** в образе пропускаются 2 начальные дорожки
  (`SYSOFFSET[4] = 2`) — способ «разрезать» один большой образ на несколько
  дисков.
* **Чтение дорожек 0–1 диска A:** подменяется данными из `cpn90sys.bin` —
  так работает «тёплый рестарт» сетевой CP/M.
* **F:** — рамдиск в памяти ГЗУ, формируется клиентской частью на самой РМУ
  (монитор в нём не участвует). Перед использованием очистить `ERA F:*.*`.

## Запись файлов (`tempfile.bin`)

Как и в C-версии, запись внутрь KDI **не поддерживается**: переименования и
удаления логируются и игнорируются. Но данные, которые CP/M пишет в новый
файл (функции 22→21→16), сохраняются в `tempfile.bin` в каталоге запуска —
точную копию записанного файла. Пример с `PIP B.DOC=BIOS.DOC` разобран в
[корневом README](../README).

## Отладка и диагностика

| Симптом | Что делать |
|---------|-----------|
| Порт не открывается | проверить имя (`-s`), права (`dialout` в Linux), что порт не занят терминалкой/модемом |
| Корвет не грузится, в логе тишина | адрес перемычками ≠ `-n`; нет согласования уровней TX/RX; проверить линию вызвонкой |
| `Пакет с неправильной контрольной суммой` | помехи на линии; уменьшить длину провода, включить `-d` и посмотреть стабильность адресации |
| `+ Передача данных: .....NNN` с буквами ошибок | РМУ не подтверждает пакеты; увеличить `ADR_DELAY` в `lan.py` |
| Загрузка «отваливается» на середине образа системы | медленный CPU/Python не успевает за 19200 — см. ниже про тайминги |

Ключ `-d` печатает `@`-строки адресации и передачи (аналог `dprintf` в C):
`@ Посылка адреса: OK`, `@ Послана команда отправки данных`,
`+ Передано N байт`.

> ⚠️ **Про тайминги.** Порт работает на 19200 бод; в C-версии байты пакета
> уходят с паузой 0,8 мс, и Python-порт честно сохраняет её
> (`BYTE_DELAY` в `lan.py`). Основной риск переноса — задержка реакции монитора
> на запрос (главный цикл на Python заметно «медленнее» C на слабом железе).
> На современном ПК/одноплатнике (RPi 3+ и выше) запас по скорости огромный;
> на очень старых/перегруженных машинах возможны таймауты опроса.

## Тесты

Тесты не требуют железа и даже `pyserial` (проверяют протокол и парсер KDI
через эмуляцию порта). Из корня проекта:

```bash
python -m unittest discover -s py/tests -v
```

Покрытие (15 тестов):

* контрольная сумма пакетов (эталонные векторы);
* framing: синхробайт, мусор перед пакетом, таймаут, битая КС;
* структура пакета на проводе (синхро/длина/номер/тип/КС/CR);
* экранирование в D-пакете: `#`→`##`, `<0x20`/`0x7F` → `#<c+0x40>`,
  старший бит данных, ограничение `MAXLEN=0x58` (84 байта данных);
* `send_data` с подтверждением Y;
* синтетический KDI: разбор инфосектора, каталог со склейкой экстентов,
  постраничная выдача 24 секторов из блоков 1–2, «файл не найден».

## Отличия от C-версии

* **Переносимость**: Windows + Linux (порт и клавиатуру инкапсулируют
  pyserial/`console.py`).
* **Ключ `-d`** — в C флаг `debug` существовал, но ключа запуска не было.
* **Валидации**: номер диска вне 0–4, адрес вне 1–15, битый инфосектор,
  короткий образ — обработаны явно (в C это было UB).
* Сообщения на консоль РМУ кодируются в **cp866**.
* Сохранено «как есть» (в т.ч. оригинальные quirks — см.
  [PORTING.md](docs/PORTING.md)): байт-в-байт протокол, тайминги, тексты
  лога, отсутствие записи в KDI, `tempfile.bin`, подмена sys-дорожек.
