# Формат образа диска KDI (CP/N-90) в реализациях `kdi.c` / `kdi.py`

KDI — образ диска для сетевой CP/N-90: физическая разметка как у реальной
дискеты Корвета (дорожки/секторы) поверх логической файловой системы CP/M.
Реализация — класс [`KdiDrive`](../kdi.py); в C-версии — `kdi.c`.

## 1. Информационный сектор (первые 0x21 байт образа)

| Смещение | Размер | Поле (C: `inf[]`) | Значение |
|---------:|-------:|-------------------|----------|
| 0x00 | 16 бит | `LoadAdress` | адрес начала загрузки |
| 0x02 | 16 бит | `RunAdress` | адрес передачи управления |
| 0x04 | 16 бит | `Count` | число загружаемых физических секторов |
| 0x06 | 8 бит | `disktype` | 1 = 8", 0 = 5.25" |
| 0x07 | 8 бит | `modulation` | 0 = FM, 1 = MFM |
| 0x08 | 8 бит | `dens` | плотность: 0 = 48 TPI, 1 = 96, 2 = 135 |
| 0x09 | 8 бит | `il_flag` | нет фактора смещения / размер таблицы перевода секторов |
| 0x0A | 8 бит | `ssize` | размер физ. сектора: 0=128, 1=256, 2=512, 3=1024 |
| 0x0B | 8 бит | `sides` | 0 = односторонний, 1 = двухсторонний |
| 0x0D | 16 бит | `spt` | физ. секторов на дорожке |
| 0x0F | 16 бит | `tracks` | дорожек на диске (с одной стороны) |
| 0x11 | 16 бит | `lspt` | логических секторов на дорожке |
| 0x13 | 8 бит | `bsh` | log2 размера единицы распределения в лог. секторах |
| 0x14 | 8 бит | `blm` | маска блока распределения |
| 0x15 | 8 бит | `exm` | маска размера |
| 0x16 | 16 бит | `dsm` | объём памяти в блоках − 1 |
| 0x18 | 16 бит | `drm` | число входов каталога − 1 |
| 0x1A | 8 бит | `al0` | какие блоки зарезервированы |
| 0x1B | 8 бит | `al1` | — под директорию |
| 0x1C | 16 бит | `cks` | размер вектора контроля директории |
| 0x1E | 16 бит | `systracks` | число системных дорожек |
| 0x20 | 8 бит | `CheckSum` | КС служебной информации |

Монитор использует: `Count, ssize, sides, spt, tracks, lspt, bsh, drm, systracks`.

## 2. Производные параметры (как в `readdir`)

```text
blocking  = (1 << bsh)                 # лог. секторов в блоке (единице распределения)
alsize    = blocking * (spt*secsz / lspt)   # размер блока в байтах образа
reserved  = (Count*secsz + (drm+1)*16) // alsize   # зарезервированных блоков перед областью данных
dirblocks = (drm+1)*16 // alsize       # блоков, занимаемых каталогом
```

Типичный стандартный диск CP/M: `secsz=128, spt=lspt=16, bsh=4` →
блок 2 КБ; каталог 128 входов = 2048 байт = 1 блок.

## 3. Каталог

Каталог начинается **на CHS-границе системной области**:

```text
seek_chs(systracks // (sides+1), systracks % (sides+1), 1)
```

(в Python защита: `max(1, sides+1)`). Элемент каталога — стандартные 32 байта CP/M:

| Смещение | Поле |
|---------:|------|
| 0x00 | `user` — номер user-раздела (в запросе маскируется `&0x1F`); **0xE5 — вход свободен/удалён** |
| 0x01–0x0B | имя+расширение, 11 байт FCB (старшие биты — атрибуты; при разборе маскируются `&0x7F`) |
| 0x0C | `ex` — номер экстента |
| 0x0F | `rc` — число 128-байтовых записей в экстенте |
| 0x10–0x1F | 8 × 16 бит — номера блоков данных в экстенте (0 = нет блока) |

Разбор: записи `ex==0` создают элемент массива, записи `ex>0` дописываются к
найденному по имени экстенту 0 (складывается `records`, доклеиваются блоки).
Если начального экстента нет — печать «нет начального экстента» и пропуск.

## 4. Чтение файла

Логические секторы файла (по 128 байт) собираются из блоков распределения.
Адрес блока `lba` в образе (как в C):

```text
offset = (reserved + lba - dirblocks) * alsize
```

Монитор читает блок целиком и выдаёт клиенту его 128-байтовые секторы по
порядку, пока не будет выдано `records` секторов — **даже если блок ещё не
кончился** (хвост блока за концом файла не передаётся).

## 5. Доступ с разных букв диска (SYSOFFSET)

В `main.c` доступ к образу идёт не по «физике KDI», а через **абсолютные
128-байтовые сектора** с пропуском `sysoffset` дорожек:

```text
offset = (track + sysoffset[drive]) * 5*1024 + (sector-1)*128
```

`sysoffset = {A:0, B:0, C:0, D:0, E:2}` — т.е. диск **E:** считает образа
2 начальные дорожки системными (способ «нарезать» один большой образ на
несколько дисков). Отдельно: чтения дорожек 0–1 диска A подменяются образом
`cpn90sys.bin` (тёплый рестарт).

## 6. Ограничения

* Поддерживается только стандартная геометрия CP/M; нестандартные образы
  (MICRODOS и т.п.) не работают — сетевой BIOS жёстко ожидает 2 системные
  дорожки, 128 записей каталога, блоки 2 КБ.
* Запись в KDI не реализуется ни в C-, ни в Python-версии (нужна полная
  файловая подсистема BDOS); записываемые данные уходят в `tempfile.bin`.
