# Перенос C → Python: карта соответствия и решения

Документ фиксирует, как исходники `pcndr` (C) отображены в Python-порт,
какие решения приняты и какие «особенности оригинала» сохранены намеренно
(или осознанно исправлены).

## 1. Файлы

| C | Python | Что перенесено |
|---|--------|----------------|
| `pcndr.h` | `common.py` | макросы `dprintf`/`abort` → функции; глобалы `debug`, `serial_timeout` → атрибуты модуля (меняются через `common.debug = 1`) |
| `std_lan.c` | `lan.py` | всё протокольное: `checksum`, `readpkt`, `sendpkt`, `pkt_A/Z/Y/N/R/D`, `send_adr`, `send_data`, `putdata`, `send_message`, `send_system` → класс `Lan` |
| `kdi.c` | `kdi.py` | инфосектор → атрибуты `KdiDrive`; массив `dir[5][500]` → `list` в объекте диска; `readdir` → `read_dir`; `readfile(drive,...)` → генератор секторов `read_file` (печать/отправка переехали в `pcndr.py`) |
| `main.c` | `pcndr.py` | `getopt` → `argparse`; настройка termios порта → параметры `pyserial`; главный цикл и `switch(fn)` — 1:1 |
| termios-код консоли из `main.c` | `console.py` | cbreak-режим (POSIX) / `msvcrt` (Windows) |
| `Makefile` | — | не нужен; зависимость только `pyserial` (`requirements.txt`) |

## 2. Функции: имя в C → имя в Python

| C | Python (`lan.py`) | Примечания |
|---|---|---|
| `checksum(buf,len)` | `Lan.checksum(buf, ln)` | статический метод, формула байт-в-байт |
| `readpkt(buf)` | `Lan.readpkt()` | длина/ошибки возвращаются так же: `len` / `0` таймаут / `-1` КС; байты — в `self.ibuf` |
| `sendpkt(buf,plen)` | `Lan.sendpkt(buf, plen)` | `usleep(800)` → `time.sleep(BYTE_DELAY)`; `tcdrain` → `ser.flush()` |
| `pkt_A/pkt_Z/pkt_Y/pkt_N/pkt_R` | `pkt_a/pkt_z/pkt_y/pkt_n/pkt_r` | те же длины 8/6/6/6/20 и поля |
| `pkt_D(pnum,dbuf,len)` | `pkt_d(pnum, dbuf, ln)` | возвращает число упакованных байт; `MAXLEN=0x58` |
| `send_adr(adr)` | `Lan.send_adr(adr)` | `adr_delay=40000 мкс` → `ADR_DELAY=0.04` |
| `send_data(dbuf,dsize)` | `Lan.send_data(dbuf, dsize)` | нумерация пакетов `0x20..0x5F` сохранена |
| `putdata(dbuf,type,start,dsize)` | `Lan.putdata(dbuf, typ, start, dsize)` | |
| `send_message(adr,buf,xclean)` | `Lan.send_message(text, xclean)` | адрес берётся из `self.nodeadr`; текст → `cp866` |
| `send_system()` | `Lan.send_system()` | те же файлы, `R7 @0xEEEE`, пауза 200 мс, 88×128 потока |
| `pchs_seek` | `KdiDrive.seek_chs` | |
| `dlocate` | `KdiDrive.locate` | |
| `readdir(ndrive)` | `KdiDrive.read_dir()` | |
| `readfile(drive,name,user)` (kdi.c) | `pcndr.readfile(ser, drives, drive, raw, user)` | печать прогресса и отправка по порту — в главном модуле; `kdi.py` отдаёт только генератор секторов |
| `timeout_on()/timeout_off(n)` | `ser.timeout = ...` | `VTIME/VMIN` termios выражаются через `timeout` pyserial; в `fn=21` таймаут снимается (`None`) — аналог `VMIN=129` |

## 3. Идиомы C → Python, применённые при переносе

| Конструкция C | Замена |
|---|---|
| `FILE*`, `fseek/fread/fwrite` | объекты файлов; `read(n)`/`seek` |
| `struct __attribute__((packed))` инфосектора/каталога | `struct.unpack_from` по явным смещениям (см. [KDI.md](KDI.md)) |
| массив `unsigned char buf[]` + длина | `bytes`/`bytearray` (слайсы вместо ручных указателей) |
| глобальный `siofd` + `read/write` | объект `serial.Serial`, читаемый побайтно с таймаутом |
| `getchar()` из cbreak-консоли | `ConsoleKeys.key()` (неблокирующий) |
| макрос `abort(...)` | `common.abort()` → `sys.exit(1)` |
| `%.11s` в `printf` | `fmt_name()`: отсечь по 0x00, ASCII-decode с заменой |
| `goto prestart` в `readpkt` | цикл-перечитывание с флагом `complete` |
| «висячие» UB при `drive>4`/битых полях | явные проверки и внятные сообщения (см. ниже §5) |

## 4. Сохранённые особенности оригинала ( намеренно, «как в C»)

1. **Контрольная сумма `fn=20`** в `readfile` — нарастающая по всему файлу,
   начинается с 0 и суммирует все переданные секторы (странность оригинала,
   оставлена: клиент её именно так и ждёт).
2. **Побайтовая отправка с паузой 0,8 мс** в `sendpkt` и байтовый прогресс
   `.`/буквы ошибок — сохранены дословно.
3. **Тексты и формат лога** (`+ Открытие файла U0: A:...`, счётчик `блок # N`,
   `\r`/`\n` логика `cr_flag`) — идентичны C (см. исключение в §5).
4. **`fn=21`: приём ровно 129 байт** без таймаута, ответ `'Y'`, в файл —
   первые 128.
5. **`marker[1] |= nodeadr`**, `sysimage`-подмена дорожек 0–1 диска A,
   `SYSOFFSET[E]=2`, `sysoffset` применяется и в печатном номере дорожки.
6. **Никакой записи в KDI**: rename/delete — только лог; новый файл —
   `tempfile.bin`; `fn=16` его закрывает.
7. Ключи `-a/-b/-e/-s/-n/-x` и дефолты (`disk/sys.kdi`, `/dev/ttyS0`, адрес 2) —
   как в C.

## 5. Осознанные отличия и исправления

| Отличие | Причина |
|---|---|
| Ключ `-d` вместо мёртвого флага `debug` | в C печатная отладка не включалась из командной строки |
| Windows-поддержка (COM-порты, `msvcrt`) | запрос пользователя; Linux-поведение не изменилось |
| Проверка адреса `-n` (1–15), номера диска (0–4) при доступе, `drive`/`sides` из инфосектора | в C — выход за массив `drives[5]` / UB |
| Короткий/битый образ KDI → понятная ошибка; нечитаемый сектор дополняется `0xE5` | в C — чтение мусора/UB |
| `tempfile.bin`: предыдущий дескриптор закрывается перед новым открытием (`fn=22`) | в C при повторном создании файла дескриптор утёк |
| Имя файла в логе: `%.11s` обрезается по 0x00 | C печатал байты до 0x00 включительно как есть; визуально почти идентично |
| Ctrl+C корректно закрывает порт/файлы и восстанавливает терминал | в C — убитый терминал после SIGINT (cbreak оставался) |

## 6. Производительность и тайминги

* Все выдержки времени (VTIME 0.1 с, ADR_DELAY 40 мс, BYTE_DELAY 0.8 мс,
  200 мс) перенесены — **протокольная совместимость по времени сохранена**.
* Python добавляет к задержке обработки пакета единицы–десятки мс (парсинг,
  печать). На фоне 40 мс `ADR_DELAY` и байтовых пауз это несущественно на
  обычном ПК; риск — только очень слабые/перегруженные машины.
* Бутылочное горлышко — побайтовый ввод/вывод: `ser.read(1)` в цикле. Для
  19200 бод это с большим запасом; при попытке поднять `MAXLEN`/скорость
  стоит перейти на `read` блоками.
