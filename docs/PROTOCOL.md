# Протокол сети ОПТС 2.0 (CP/N-90) в реализациях `std_lan.c` / `lan.py`

Документ описывает всё, что монитор (`NDR`/`pcndr`) обменивает с клиентской
частью CP/N-90 в Корвет-РМУ по последовательному порту. Реализация —
класс [`Lan`](../lan.py); в C-версии — `std_lan.c`.

Физический уровень: **19200 бод, 8O1** — 8 data bits, **odd parity**
(`PARENB|PARODD` в C, `PARITY_ODD` в Python), 1 stop bit, без flow control. Логика уровней TTL согласывается переходником (схемы в `sch/`).

## Общая картина сеанса

```text
МОНИТОР (мастер)                          КЛИЕНТ (РМУ, CP/N-90)
   |  маркер опроса FF 80|адрес  ------------>  |   (опрос «есть кто?»)
   |  <-----------------------------------------  ответ: командный пакет 34 байта
   |  'Y' (КС верна) / 'N' (КС неверна) ------>  |
   |  <---- данные/подтверждения по запросу --  |   (зависит от функции)
```

Монитор — всегда мастер: он опрашивает сеть маркером, на адресных пакетах
указывает адрес РМУ, от него клиенту перекидываются образы памяти и сообщения.

## 1. Пакеты данных («сетевые» пакеты ОПТС)

Используются при загрузке системы и адресации. Структура «на проводе»:

```text
offset  поле
0       0x01            синхробайт начала
1       L = len + 0x1D  длина пакета со сдвигом (len — реальные байты)
2       N               номер пакета (0x20..0x5F, затем цикл к 0x20)
3       тип             ASCII-буква пакета
4..     параметры/данные
len-2   C               контрольная сумма
len-1   0x0D            конец пакета (CR)
```

### Контрольная сумма

Считается по байтам `[1 .. len-3]` (от байта длины до последнего данных,
**без** синхробайта, самой КС и CR):

```python
csum = sum(buf[1:len-2]) & 0xFF
ks   = (((csum >> 6) + csum) & 0x3F) + 0x20
```

Проверка в `readpkt`: вычисленная КС сравнивается с байтом `len-2`.

### Типы пакетов мастер→клиент

| Буква | Длина | Поля | Назначение |
|-------|-------|------|------------|
| `A` | 8 | `[4]='0'+mode`, `[5]` = `'1'` (broadcast) или `"%01X"` адреса | адресный: «говорит мастер, слушай узел X» |
| `R` | 20 | `[4]='0'+type`, `[5..8]="%04X"` адрес памяти | команда клиенту: жди данные по адресу `addr` |
| `D` | 6..0x58 | упакованные данные | пакет данных (экранирование — ниже) |
| `Y` | 6 | — | подтверждение принятого |
| `N` | 6 | — | ошибка принятого |
| `Z` | 6 | — | конец данных; после `Z` мастер читает ответ |

### Типы данных в `R`-пакете (поле mode)

| 0 | текстовое сообщение **с очисткой экрана** |
|---|-------------------------------------------|
| 1 | образ GRAM |
| 2 | бейсик-программа |
| 3 | образ блока RAM |
| 5 | тело COM-сообщения |
| 6 | флаг наличия COM-сообщения |
| 7 | образ блока RAM **с передачей управления** на начало блока |
| 8 | текущий счётчик пакетов |
| 9 | текстовое сообщение без очистки экрана |

Загрузка: загрузчик `cpn90ldr.bin` идёт как `R mode=7 addr=0xEEEE`
(т.е. после приёма управление передаётся ему), за ним `cpn90img.bin`
просто потоком 88×128 байт без протокола (загрузчик РМУ уже принимает).

### Экранирование данных в `D`-пакете

7-битный «текстоподобный» канал: каждый байт данных кладётся в пакет так,
чтобы в потоке не встречались управляющие коды и сам префикс `'#'` (0x23):

```text
c = байт данных, cs = c & 0x80 (старший бит сохраняется в выходном байте)
c &= 0x7F
если c == '#':            в пакет идёт 0x23 0x23  (префикс удваивается)
если c < 0x20 или c==0x7F: в пакет идёт 0x23, затем ((c+0x40)&0x7F)|cs
иначе:                     в пакет идёт c|cs
```

Ограничение: весь пакет не более `MAXLEN = 0x58` байт (число взято из ОПТС) →
не более **84 байт «сырых» данных** в пакете без экранирования.
`pkt_d` возвращает число реально упакованных байт — по нему `send_data`
сдвигает указатель.

### Порядок адресации и передачи (`putdata`)

1. `send_adr(adr)` — до 10 попыток: пауза `ADR_DELAY=40 мс` → `A mode=1` с
   номером от 0x20 → читать ответ; ждём пакет с `[3]=='Y'`.
2. `R`-пакет (тип+адрес) → читаем подтверждение, ждём `Y`.
3. Цикл `D`-пакетов: на каждый — читаем ответ, ждём `Y`, иначе повтор
   (до 10 попыток); номер пакета инкрементируется с циклом `0x20..0x5F`.
   На консоль печатается прогресс `.` (буквы ответов-ошибок печатаются как есть).
4. `Z` → читаем финальный ответ.

`send_data` с нулевой длиной возвращает 1 (специальный случай «запуск с
адреса» — обход контроля ошибок), иначе — число переданных байт.

### Приём (`readpkt`)

* ждём синхробайт `0x01` (мусор до него игнорируется, при таймауте — возврат 0);
* байт длины → реальная длина `plen = (L-0x1D) & 0xFF`;
* читаем до `plen` байт; если в теле попался `0x01` — считаем, что начался
  новый пакет, и **перечитываем всё заново** (`goto prestart` в C);
* КС верна → длина пакета; иначе `-1`.

## 2. Командный пакет запроса (клиент → монитор)

Во время работы сетевой CP/M запрос приходит **в ответ на маркер опроса**.

```text
Монитор:  FF 80|addr                       (2 байта, addr = 1..15)
Клиент:   b0 b1 b2 ... b33                 (34 байта, побайтно, с таймаутом 0,1 с)
```

Раскладка командного пакета (из `main.c`; `pkt` в Python):

| Смещение | Поле |
|----------|------|
| 0 | первый байт ответа — используется только как признак «есть ответ» |
| 1 | `[4:0]` — номер user-области CP/M (`user = b1 & 0x1F`) |
| 2 | код функции (`fn`) |
| 3–5 | для `fn=0`: диск, дорожка, сектор |
| 4–14 | имя файла, 11 байт CP/M-FCB (`"ИМЯ   РАСШ"`, старшие биты могут быть атрибутами) |
| 0x14–0x1F | новое имя файла (для `fn=23`, переименование) |
| 32 | номер диска для файловых функций |
| 33 | контрольная сумма: `sum(b1..b32) & 0xFF` |

Монитор при верной КС отвечает байтом `'Y'` (при ошибочной — `'N'`) и
обрабатывает функцию. Байты `[0]` и `[1]` в сумму входят только `[1..32]`.

### Коды функций и отклики

| fn | Операция | Поля | Ответ монитора |
|----|----------|------|----------------|
| 0 | **абсолютное чтение сектора** | drive, track, sector | 128 байт сектора + 1 байт КС (сумма байт сектора) |
| 15 | открытие файла | диск, имя | только лог |
| 16 | закрытие файла | диск, имя | только лог; закрывает `tempfile.bin` |
| 19 | удаление файла | диск, имя | только лог (игнорируется) |
| 20 | **последовательное чтение файла целиком** | диск, имя | поток `N×128` секторов + байт КС (нарастающая сумма по всем секторам, как в C) |
| 21 | **запись блока файла** | диск, имя | монитор читает **129 байт** без таймаута, отвечает `'Y'`, первые 128 пишет в `tempfile.bin` |
| 22 | создание файла | диск, имя | открывает `tempfile.bin` (wb) |
| 23 | переименование | старое+новое имя | только лог (игнорируется) |
| 36 | SETRAN | диск, имя | только лог |
| прочее | — | — | лог «неопределённая функция» |

Особенность `fn=0`: чтения **дорожек 0–1 диска A** монитор подменяет данными
из `cpn90sys.bin` — образ «тёплой» системы, который клиент перечитывает при
RELOAD. Для диска E к номеру дорожки прибавляется смещение 2 (`SYSOFFSET`).

### Опрос без клиента

Если на маркер никто не ответил за таймаут (0,1 с), `read` возвращает 0 байт —
монитор просто идёт дальше по циклу (проверяя клавиши консоли). Так же
«ищет» сеть оригинальный NDR.

## 3. Тайминги (сохранены из C)

| Константа | Значение | Где |
|-----------|----------|-----|
| `VTIME` | 0,1 с — таймаут ожидания байта | опрос маркера, чтение пакета |
| `ADR_DELAY` | 40 мс — пауза перед адресным пакетом (РМУ «очухиваются») | `send_adr` |
| `BYTE_DELAY` | 0,8 мс — пауза между байтами пакета | `sendpkt` |
| пост-загрузочная пауза | 200 мс — инициализация загрузчика в Корвете | `send_system` |

Увеличение `ADR_DELAY` повышает надёжность на длинной линии ценой скорости
(в C — переменная `adr_delay`).
